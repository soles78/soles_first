# 대구 북구청 보도자료 문체 가이드라인

대구 북구청 이름으로 내는 보도자료를 쓰거나 고칠 때 따르는 가이드다. 구청장 기고문·연설문·인터뷰는 이 가이드의 대상이 아니다(별도 가이드 필요).

- 근거 코퍼스 · 공공데이터포털 「대구광역시 북구_보도자료」(데이터 번호 15149016, 수정일 2026-09-14, 이용허락범위 제한 없음) 1,412건, 등록일 2018-02-28~2026-08-14. 사본은 `corpus/buk_press_2018-2026.csv`.
- 수치 출처 · `scripts/analyze_press.py`가 만든 `stats_all.json`(전체)과 `stats_2024-.json`(2024-01-01 이후 499건). 아래 표의 % 는 별도 표시가 없으면 2024년 이후 499건 기준이다.
- 윤문 원칙 · 「AI 티」 제거와 세 가지 불변식(새 사실 금지·고정 구역 보존·뜻 뒤집기 금지)은 [slop-rewrite](https://github.com/byungjunjang/slop-rewrite)의 `principles/`를 따른다. 그 저장소에는 라이선스 파일이 없으므로 원문을 복제하지 않고 요지만 적용했다.
- 수치는 「지금까지 이렇게 써 왔다」는 관찰이다. 수치에 맞추려고 문장을 억지로 자르거나 늘리지 않는다.

## 2. 지킬 형식 (관찰에서 굳힌 것)

1. **첫 문장**: 「대구 북구청(구청장 ○○○)은 ○월 ○일(요일), ~했다.」 누가·언제·무엇을 한 문장에 둔다. 보건소·센터가 주체면 「대구 북구보건소(소장 ○○○)는」처럼 그 기관을 쓴다. 이름은 반드시 확인한 것만 쓴다.
2. **본문 단위**: 문단마다 ○ 하나. 한 ○ 에 한 가지 사실(배경·내용·효과·일정 중 하나).
3. **순서**: 무엇을 했나 → 왜 했나(이전 불편·문제) → 구체 내용 → 앞으로 일정 → 구청장 인용. 배경 설명이 첫 ○ 에 오지 않게 한다.
4. **종결**: 해라체 평서(-했다/-한다/-이다). 계획은 「~할 계획이다」·「~할 예정이다」 가운데 문서 안에서 하나로 쓴다. 확정되지 않은 일을 「~했다」로 쓰지 않는다.
5. **날짜**: 「7월 1일(수)」처럼 숫자+요일. 연도가 바뀌는 시점이 아니면 연도는 사업 기간에만 붙인다.
6. **나열**: 3개 이상 항목은 「▲A ▲B ▲C」로 묶는다.
7. **인용**: 구청장 인용은 끝 ○ 에 한 번. 두 문장이면 「"…"라며, "…"라고 말했다.」 맺음은 「말했다」로 통일한다.
8. **제목**: 「대구 북구, ~」 또는 「대구 북구청, ~」 다음에 핵심 사실(무엇을 몇 개·어디에). 따옴표 카피는 본문에 근거가 있는 구체 문구일 때만 쓴다.

## 3. 덜어 낼 것 (AI 티·상투어)

| 유형 | 예 | 고치는 법 |
|---|---|---|
| 평가어·과장 | 대폭 향상, 한층 세련되게, 획기적, 명품 | 무엇이 몇 개·어디서 어디로 바뀌었는지 사실로 바꾼다. 사실이 없으면 지운다 |
| 확인 안 된 효과 | 만족도를 높였다, 큰 호응을 얻었다, 꾸준한 사랑 | 설문·이용 수치가 있으면 그 수치로, 없으면 지운다. 수치를 지어 넣지 않는다 |
| 목적 상투구 | ~이 더욱 쾌적하고 편리하게 ~할 수 있도록 | 이어지는 사실 문장이 목적을 이미 보여 주면 지운다 |
| 은유 카피 | 「풍경에 편안함을 채우다」 | 제목에는 사실을, 은유는 꼭 필요할 때 부제가 아닌 인용에서만 |
| 문두 접속부사 | 또한·이에·한편 | 지워 보고 뜻이 통하면 뺀다 |
| 다짐 상투구 | 앞으로도 ~ 최선을 다하겠다, ~할 수 있도록 노력하겠다 | 인용 안에서 구체 다음 일정(언제 무엇을)으로 바꾼다. 확정 일정이 없으면 다짐 한 문장으로 줄인다 |
| 번역 투·이중 피동 | ~에 있어서, 되어지다, 가독성이 떨어지다 | 「~에서」, 「되다」, 「글씨가 잘 보이지 않다」 |
| 무생물 주어 + 사람 동사 | 사업이 ~에 중점을 두었다 | 주어를 북구청으로 바꾼다 |

## 4. 바꾸지 않는 것

- 숫자·날짜·요일·기관명·성명·직함·사업명(작은따옴표 안 명칭)은 글자 그대로 둔다. 원문 숫자로 합계·증가율을 새로 계산해 넣지 않는다.
- **배포·승인된 구청장 인용은 글자 그대로 둔다.** 초안 단계 인용은 홍보팀이 고칠 수 있지만, 고친 안은 본문에 바로 넣지 않고 「작성자 확인」에 제안으로 적어 결재를 받는다.
- 「검토 중」·「추진 예정」을 「확정」·「완료」로 올리지 않는다.
- 사실 확인이 안 된 항목은 본문에 넣지 않고 작성자 확인 목록에 [확인요망]으로 적는다.

## 5. 압축 프롬프트

```
아래 규칙으로 대구 북구청 보도자료를 고쳐라. 원문에 없는 숫자·이름·인용·효과를 더하지 마라.

[형식] 첫 문장은 「대구 북구청(구청장 ○○○)은 ○월 ○일(요일), ~했다.」로 누가·언제·무엇을 한 문장에 둔다. 문단은 ○ 하나에 사실 하나. 순서는 한 일 → 이전 문제 → 구체 내용 → 일정 → 구청장 인용. 해라체 평서(-했다/-한다)로 쓰고 계획은 「~할 계획이다」 하나로 통일한다. 3개 이상 나열은 ▲로 묶는다. 제목은 「대구 북구, 」 뒤에 핵심 사실을 쓴다.

[덜기] 평가어(대폭·한층·획기적·명품·세련된)는 사실로 바꾸거나 지운다. 확인 안 된 효과(만족도 향상·큰 호응·꾸준한 사랑)는 지운다. 「~할 수 있도록」 목적 상투구, 문두 접속부사(또한·이에·한편), 은유 카피, 번역 투(~에 있어서, 가독성)는 뺀다. 문장이 100자를 넘고 사실이 둘 이상이면 나눈다.

[지키기] 숫자·날짜·요일·기관명·성명·사업명은 글자 그대로. 배포·승인된 인용은 고치지 말고, 고칠 안은 끝의 「작성자 확인」에 제안으로만 적는다. 확정 수준(검토·예정·완료)을 바꾸지 않는다. 뺀 문장은 작업 기록에 원문 그대로 남긴다.
```
